# План восстановления оставшихся 18 подписок

28 сентября 2026. Проверена текущая production-база, публичные страницы и RSS из локальной сети и с сервера 158.160.186.87. Это исследование и план: подписки, расписания, адреса, секреты и production-конфигурация в этом этапе не изменялись.

## Почему снова 18

Предыдущий итог был 16. К ним добавились Dropbox (HTTP500) и Greptime (обрыв тела ответа). У одиннадцати прежних источников нет ready/leased задач: старое исчерпание попыток остановило их до предыдущего исправления. У остальных семи повторные циклы есть. Восстанавливать расписание нужно после проверки подходящего коллектора и адреса; сбрасывать красный статус вручную нельзя.

## Что нужно изменить в общей доставке

1. Сначала использовать рабочий официальный RSS. Если он сломан, отдельно настроить HTML-рецепт и проверить идентичность уже сохранённых статей. RSS GUID нельзя без проверки заменить URL.
2. Отказаться от двух статических бесплатных прокси как гарантированного маршрута. В свежих пробах первый недоступен, второй даёт и реальные ленты, и таймауты. Нужны измеряемое здоровье по хосту/маршруту, карантин отказавших адресов, периодическая проверка пула, отдельный бюджет времени на каждый маршрут в рамках общего deadline. HTTP429 должен сохранять Retry-After, а не вызывать смену IP ради обхода ограничения.
3. Для постоянной эксплуатации — проверенный частный внешний выход либо управляемый сборщик. Сначала испытать точные проблемные URL, потом выбирать тариф. Обычный зарубежный VPS не гарантирует снятия anti-bot; для некоторых сайтов может потребоваться разрешённая браузерная сессия.
4. Разнести опрос Reddit и других общих origin во времени; вместо серии быстрых запросов при429 применять длинный cooldown и случайный сдвиг. Все интервалы должны быть явными настройками. При ошибке чтения сохранять прежние данные и повторять целый документ, не принимать оборванный XML.
5. После изменений восстановить регулярные задачи для всех18. Приёмка: настоящий парсинг, публикация в библиотеке, сохранность ID/прочитанности, следующий успешный цикл. Один HTTP200 или исчезновение ошибки не доказывают читаемость статьи.

## Бесплатный и платный внешний выход

Бесплатный эксперимент: Cloudflare Worker для публичных RSS и Browser Run для страниц с JS. Workers Free включает100000 запросов/день; Browser Run —10минут браузера/день. Нужен аккаунт/API-доступ. Это кандидат для испытания, а не доказанное решение: Cloudflare прямо указывает, что Browser Run определяется как бот и не позволяет ротацию исходящих IP. Для Qlik/Oracle/anti-bot сначала нужны пробные ответы точных URL.

- [Workers: официальный тариф](https://developers.cloudflare.com/workers/platform/pricing/).
- [Browser Run: тариф](https://developers.cloudflare.com/browser-run/pricing/).
- [Browser Run: bot identification и IP](https://developers.cloudflare.com/browser-run/faq/).

Если бесплатный выход не подходит, можно испытать небольшой pay-as-you-go пул частных прокси. Например, [Bright Data](https://brightdata.com/pricing/proxy-network/residential-proxies) предлагает PAYG без месячного обязательства; residential требует проверки аккаунта. До оплаты/интеграции необходим тест наших URL и явный бюджет. Покупок и регистрации аккаунтов не было.

Для аутентифицированного Zhihu нельзя использовать текущий публичный proxy-транспорт: он намеренно запрещает cookies и токены. Нужны доверенный закрытый маршрут и шифрованное хранение сессии.

## Ограничения платформ и доказательства

Reddit API требует зарегистрированного OAuth и явного одобрения доступа; создать бесплатный ключ и гарантированно читать любые сообщества нельзя. [Data API Wiki](https://support.reddithelp.com/hc/en-us/articles/16160319875092-Reddit-Data-API-Wiki), [Responsible Builder Policy](https://support.reddithelp.com/hc/en-us/articles/42728983564564-Responsible-Builder-Policy).

Zhihu-кандидаты проверены по текущему исходному коду [RSSHub posts](https://github.com/DIYgod/RSSHub/blob/master/lib/routes/zhihu/posts.ts) и [session utility](https://github.com/DIYgod/RSSHub/blob/master/lib/routes/zhihu/utils.ts); аутентифицированная поставка ещё не продемонстрирована.

Telegram-бот не читает произвольный сторонний канал, куда его не добавили. Для расширенной истории [messages.getHistory](https://core.telegram.org/method/messages.getHistory) требует пользовательской сессии. [Bot FAQ](https://core.telegram.org/bots/faq#what-messages-will-my-bot-get).

Локальные артефакты: `.inoreader-state/attention-next/current.json`, `active-jobs.json`, `social-{local,server}.jsonl`, `social-delivery-options.md`, `alternates/`, `network/`. Эти проверки не заменяют production-парсинг и два успешных регулярных цикла.
