## Сделано

- Исправлены десять рецептов HTML: выбираются реальные статьи без повторяющихся презентационных ссылок. Проверены CSS и XPath, ссылки featured-карточек, текстовые и графические варианты ссылок, пагинация. Извлечение не ограничено одним featured-блоком.
- В Claude сохранён охват трёх страниц: исходная и две реальные publisher-authored ссылки пагинации. Проверка извлекает 51 уникальную публикацию. Параметр пагинации привязан к текущей разметке сайта и потребует обновления при её изменении.
- Для StreamNative восстановлена отсутствовавшая строка рецепта из точного прежнего SourceKind, затем применён новый рецепт через API с контролем версии. Идентификаторы источника и подписки сохранены.
- Только для Yandex, после отдельного согласия пользователя, включён явный режим объединения полностью идентичных XML item. Конфликтующие версии одной идентичности по-прежнему останавливают сбор; остальные RSS остаются строгими.
- Проверены 96 бесплатных HTTP CONNECT-прокси ProxyScrape. Первоначальный рабочий кандидат умер при повторной проверке и не включён. Развёрнут ограниченный список повторно проверенных маршрутов и резервных адресов через общий безопасный HTTP-клиент. Chromium использует тот же проверяемый сетевой слой: сам по себе браузер не меняет исходящий IP.
- Повторные попытки и восстановление периодических задач выполняются ограниченно, с диагностикой и учётом Retry-After. Защитные страницы 403 не объявляются успешными фидами. Публичные прокси не получают cookies, токены или AI-запросы.

- DATAREON: подтверждено, что сервер обрывает запросы с ETag/Last-Modified до HTTP-заголовков. Общий клиент однократно повторяет только безопасный условный GET без кеш-валидаторов, с тем же deadline и новой проверкой DNS/IP. Регрессионные тесты и production-событие `conditional_cache_recovery` подтверждены; сбор успешен.
- Исправлена взаимная блокировка heartbeat и транзакции сбора. Продление аренды больше не приостанавливает commit, удерживающий нужную ему строку. При выкладке точечно откатили идентифицированную зависшую транзакцию с истёкшей арендой; долговечная задача сохранена для повторного выполнения. После выкладки: ноль зависших более минуты транзакций, ноль заблокированных соединений.
- Удалены только дубли **расписания** четырёх источников из активного выполнения: строки задач сохранены как superseded, выбран наиболее поздний cooldown с исходными попытками. Статьи не удалялись. Для SQL Ninja отдельно обеспечен регулярный CollectWebFeed.

## SQL Ninja: сбор восстановлен, тело требует исправления

Сохранены 19 `source_records`, доставлены 19 статей библиотеки; ошибка коллектора сброшена. Используется публичный список `https://t.me/s/sql_ninja_info`, исходный URL подписки и абсолютные ссылки постов сохранены. Для 17 постов доступен текст, для двух — только авторские уведомления Telegram о недоступном медиа; такие посты не отброшены и не получили вымышленных заголовков.

Однако проверка настоящего API статьи `/163` выявила ограничение: полный текст поста оказался заголовком, а `bodyHtml` содержит оболочку Telegram с Download/Context/Embed вместо поста. `fullText=ready` здесь не означает читаемое тело. HTML публикации сохранён в `SourceRecord.feed_content_html`, но общий fulltext-проход загружает permalink и не использует это поле. Это **не считается полностью восстановленной читаемой поставкой**. Нужен отдельный явный контракт выбора сохранённого тела или Telegram-экстракции; молчаливой подмены URL/контента в этом изменении нет.
