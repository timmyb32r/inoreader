## Подтверждения по исходникам

Номера строк относятся к `ARTICLE_SNAPSHOT.text` в соответствующем `request.json`, начиная с единицы.

### #609: исправлена субъектная связь без потери механизма

**Source L19:** `A service that writes to a table another team reads from.` Draft: «пишет в таблицу другой команды». Review: «сервис пишет в таблицу, которую читает другая команда». Это точное исправление: факт чтения не доказывает принадлежность таблицы. Здесь второй этап даёт конкретную полезную коррекцию, а не косметическое перефразирование.

Из той же **L19** восстановлено, что удаляемую колонку продолжает использовать **background job**. Это добавление из исходника, не новый придуманный контекст. Source **L17** говорит о обычно правильных syntax/patterns/names, **L19** — работающем коде, применённом не к тому объекту; review «код обычно корректен, но применён не к тому объекту» не обещает безошибочность AI-кода.

Source **L41**: размер diff перестал быть полезным сигналом; вместо него blast radius. Review теперь говорит именно о полезности сигнала, а не будто была проверена способность размера статистически предсказывать аварии. **L25–27** подтверждают четыре выхода AI reviewer и его отказ от bikeshedding имён/refactor suggestions; это уточнение не исключает проверку coding standards, явно оставленную в списке.

Сохранены существенные условия:

- **L37–39:** team → handful of customers → 10% → everyone, выключение флага; `often` не превратилось в «всегда», stateful-изменения всё ещё требуют rollback plan.
- **L47:** 3 000-line low-risk PR имеет flag, **нет migration, нет shared-contract changes**, сначала внутренние пользователи. Все условия остались.
- **L49:** 12-line index change на таблице с 50 million rows — high risk. Не перепутаны строки PR и строки таблицы.
- **L57–59:** Why/What заполняет человек; rollback/revert plan обязателен. Эти требования сохранены.
- **L79:** `80%+ of PRs by count are AI-authored`. Review теперь явно пишет «более 80% PR **по количеству**». Это не доля строк кода и не универсальная граница безопасности. Формула про diminishing/compounding returns остаётся выводом Rootly из статьи; независимым измерением review её не называет.

Описание деятельности Rootly отсутствует в основном article body, но разрешено заранее проверенным справочником [verified-company-context.md](verified-company-context.md). Поэтому сохранение этого определения не считается добавлением неподтверждённого бизнеса.

### #127: удалён второстепенный клиент, основной смысл сохранён

**L19** связывает Redshift JDBC/DatabaseMetaData с SQL Workbench/J; **L21** связывает PostgreSQL ODBC с RStudio. DBeaver отдельно перечислен в **L23, L48–49** среди catalog query/client compatibility примеров. Проверка убрала его только из фразы про driver API; сами `pg_catalog`, `information_schema`, `svv_*` и около 35 запросов сохранены. Нет потери главной идеи или утверждения, будто DBeaver вообще не тестируется.

**L1, L148** по-прежнему поддерживают разделение Current/Trailing и buffer window. Draft и review одинаково пишут «получают патч сразу» и «с задержкой 1–6 недель»; source задаёт 1–6 **недель проверки до запланированного production deployment**. Это timing caution из предыдущего аудита: review его не смягчил. Не объявляю диапазон неверным, но формулировку нельзя трактовать как доказанную гарантию мгновенной установки Current вне расписания.

**L13–27, L61** подтверждают triggers, pipeline, драйверы, catalogue queries, benchmark baseline и reporting. **L156** подтверждает event-driven task; **L160–174** напоминают об ongoing costs ресурсов. Output не добавляет старую ошибочную гарантию бесплатности всего контура вне test run. Имя Eva Donaldson — **L194–196**.

### #464: правильный draft сохранён, новой privacy-гарантии нет

**L5** прямо описывает локальное выполнение evaluator, генерацию кандидатов API и возврат результатов. Ни draft, ни review не добавляют «код не покидает инфраструктуру», «наружу идут только результаты» или обещание произвольного private-code workflow. В этой паре нельзя приписывать review исправление privacy: требуемой ошибки в draft уже не было.

**L9–11** подтверждают Klarna training throughput 2×, JetBrains latency −15–20%, Kinaxis accuracy +22% и runtime −90%; **L27** — vendor/customer testimonials, отсутствие independent benchmarks и disclosed pricing. **L25** поддерживает измеримую автоматизируемую evaluation function, **L31** — опасность непроверенных свойств. Проверка не удалила ни эти caveats, ни attribution. Имя автора — **L37**.

Завершённый JSON/неизменность не снимают style debt: **L7** workflow и четыре класса задач переданы длинными перечислениями; WMAPE не определён. Review сохраняет, а не улучшает эту форму.

### #826: важные границы не потеряны, cautions не устранены

**L7, L9–11** поддерживают rebase совместимых существующих application images, замену run-image layers и отсутствие application rebuild/source access/CI queue в самом rebase. Output отдельно оставляет **testing, promotion, deployment** для production и **пересборку application dependencies**. Это сохраняет необходимые границы локальной операции; обобщения «весь rollout за миллисекунды» нет.

**L13** подтверждает BellSoft/Paketo/Alpaquita и sign/attest/test/promote. **L15–17** с коммерческими SLA полностью опущены ещё первой стадией; review не вернул старое смешение free catalog и paid remediation guarantee.

**L19:** 6,292 images, nearly 61% repositories, vulnerable application dependencies `in every tag examined`. Число 6292 в output эквивалентно 6,292; автоматический numeric-token flag — формат разделителя, не другая выборка. Repository denominator сохранён. Формулировка «во всех тегах» всё ещё опускает examined; контекст исследования ограничивает возможное чтение, поэтому это оставлено как **caution**, а не превращено без дополнительных оснований в definite universal claim.

Определение «Open Container Initiative — стандартный формат контейнерных образов» по-прежнему неточно различает инициативу и спецификацию/формат. Source не даёт этого пояснения, внешнего поиска этот аудит не проводил; это тот же terminology caution, а не новая ошибка второй стадии. **L21–23** подтверждают tradeoff control/rebase-ability. Имя автора — **L27**.

## Ограничения вывода

На этой четвёрке есть **одна подтверждённая исправленная factual-связь** и дополнительные точные уточнения. В двух случаях checker не изменил ни одного сегмента. Это полезно для сохранения уже верного содержания, но не доказательство надёжности на иных видах ошибок и не замена авторской оценки стиля. Оставленные cautions и stylistic failures перечислены явно. Проверка не вводила новых тем, вымышленных цифр или мнений от лица пользователя; длинные исходные пересказы при этом не стали короткими.
