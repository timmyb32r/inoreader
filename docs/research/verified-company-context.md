## Короткая доказательная запись

### Rootly

- URL: <https://rootly.com/>; заголовок страницы **AI-native incident management platform | Rootly**.
- Короткий исходный фрагмент: **“AI for on-call and incident response.”**
- On-Call описывает paging/scheduling/coverage; Incident Response — автоматизацию incident workflows, в том числе в Slack/Teams. Этого достаточно для определения через инженерные дежурства и управление инцидентами. Раздел Retrospectives также описывает последующий разбор, но он не обязателен для короткого пояснения.
- Связь со статьёй #609 подтверждена URL `https://rootly.com/blog/why-we-got-rid-of-our-small-pr-rule` в `pairs/final-02.jsonl`. Внешнее определение не является доказательством причин или результатов отмены small-PR rule.

### Prequel

- URL: <https://www.prequel.co/>; заголовок страницы **Prequel: The API for Data Warehouse Integrations**.
- Короткий исходный фрагмент: **“The API for data warehouse integrations”**.
- Следующий абзац явно описывает оба направления: из собственной платформы в хранилище клиента и из клиентского хранилища в платформу. Навигация различает Data Export и Data Import; это платформа интеграции/переноса данных, а не само хранилище.
- Связь со статьёй #1048 подтверждена URL `https://www.prequel.co/blog/physical-replication-for-iceberg-tables/` в `pairs/final-02.jsonl`. **Сопоставление только по названию Prequel недостаточно:** запись относится к домену `prequel.co`; профиль одноимённой компании с другим доменом сюда переносить нельзя.
- Не выводить из этого общего описания, что Prequel разработала Apache Iceberg, является СУБД или гарантирует универсальную совместимость/определённую задержку репликации.

### Razorpay

- URL: <https://razorpay.com/about/>; заголовок страницы **About Razorpay and The Team Behind it**.
- Короткий исходный фрагмент: **“A comprehensive payments suite in India”**.
- About описывает приём/обработку платежей и выплаты для бизнеса, доступ через API. Географический контекст Индии также подтверждён расположением головного офиса в Bangalore и начальным определением компании в кейсе AWS.
- Дополнительное основание: `sources/final02-187-direct.txt`, строка **5**, описывает Razorpay как индийскую компанию финансовых решений и перечисляет payment gateway, RazorpayX и Razorpay Capital. Это определение доступно непосредственно в ARTICLE_SNAPSHOT #187; для данной статьи оно не требует внешней догадки.
- **Не называть Razorpay банком.** Официальный About поясняет, что банковские счета/карточные продукты предоставляются партнёрскими банками, а RazorpayX сама не имеет банковской лицензии. Для данной задачи достаточно общего определения платёжного бизнеса; правовая квалификация/актуальные лицензии отдельно не исследовались.

## Отдельное терминологическое основание: fsync

[Документация PostgreSQL 18](https://www.postgresql.org/docs/18/runtime-config-wal.html#GUC-FSYNC)
различает настройку fsync и системный вызов fsync(), посредством которого
изменения синхронизируются с диском. Частота выполнения таких вызовов не является
определением самого вызова. В review-v2 добавлено это ограниченное проверенное
основание после того, как review-v1 сохранял ошибочную дефиницию. Оно не даёт
универсальной гарантии поведения оборудования и не доказывает throughput
конкретного benchmark. Прямое получение POSIX-страницы вернуло403; её содержимое
не использовано как прочитанное основание. Проверено2026-09-27.
