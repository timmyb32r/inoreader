## Подтверждения существенных границ

Номера строк относятся к `ARTICLE_SNAPSHOT.text` из `request.json` соответствующего запуска в реестре ниже, считая строки с единицы. Запросы находятся в `.inoreader-state/style-research/experiments/<run>/request.json`; содержимое источника одинаково для none/high и первоначального candidate01.

**#198, Spark Connect и лимиты.** Source L39 задаёт managed authenticated/authorized endpoint; L336 — TLS и короткоживущие токены; L340–354 — IAM и права. High передаёт смысл «безопасного» более непосредственно. L77 говорит о настраиваемых defaults, поэтому none потерял условие у 60 workers. L293 и L325 задают `ALL_DONE`, то есть запуск cleanup при любом исходе предшествующих задач; это не доказательство безусловного успеха самой очистки. Оба режима сохранили описанную в источнике идею оплаты активных сессий/по использованию, но high не повторил полезную оговорку об оплачиваемом idle из L59. Это опущенный caveat, не прямое обещание бесплатного простоя.

**#127, стоимость.** Source L156 связывает pay-only с compute каждого тестового запуска. Source L158–174 отдельно требует удалить связанные ресурсы, чтобы не нести дальнейшие затраты: среди них NAT gateway, S3 bucket, ECR и stack. Output high добавил «вся автоматика» и не сохранил scope compute. Он не должен создавать впечатление, что вне времени теста весь развёрнутый контур бесплатен. Это конкретное неподтверждённое обобщение, а не спор о точном тарифе AWS; внешние цены в этой проверке не использовались.

**#127, tracks.** Source L1 задаёт Current для Dev/QA, Trailing для Production и окно проверки; L148 объясняет назначение разделения. В обоих новых outputs осталось ровно это распределение. Ни «ранний трек получения обновлений» для Current, ни противопоставленная роль отложенного production track для Trailing не выражены как определения. Жирное начертание не заменило ответ на вопрос пользователя «что это такое».

**#464, privacy.** Source L5 устанавливает client-side evaluator, генерацию кандидатов API и отправку результатов обратно. Source не гарантирует, что весь код/весь outbound-трафик остаётся внутри клиента. None снова утверждает безусловную гарантию. High ограничивается описанием ролей и возможностью работы с непередаваемым кодом; enterprise framing статьи даёт последнему некоторую опору, поэтому это caution, **не тот же по силе definite**, что unqualified no-egress. Review также не утверждает обратного — будто private code обязательно отправляется.

**#464, objective.** Source L3 говорит об optimized code относительно пользовательской функции; L25 перечисляет разные цели, включая forecasting accuracy/WMAPE, distance, throughput, area и power. None превратил это в «пока не найдёт более быстрый или компактный код». Улучшение произвольной цели не обязано ни ускорять программу, ни уменьшать код. High этого сужения не делает. Его числа 2×, 6 000/три недели, 15–20%, +22%, −90%, Spanner −20% соответствуют L9–11.

### #882: CTO, функция и компания — не смешивать

В source L3 спикер сам называет свою позицию CTO of GFXReconstruct и сразу объясняет её через ответственность за направление продукта и часть исполнения. Далее он отдельно говорит о своей фирме как software consultancy. В L15 обсуждается руководство graphics capture/replay project; L27 — развитие программного инструментария. Snapshot не даёт основания автоматически считать **GFXReconstruct названием работодателя**.

Output v13 пишет «CTO GFXReconstruct», **не «CTO компании GFXReconstruct»**. Поэтому подтверждённой подмены проекта компанией в этом ответе нет: титул соответствует самоописанию докладчика. Остаётся caution понятности — без слова «проект» читатель может привычно принять название после CTO за компанию. Нельзя исправлять эту неоднозначность выдуманным названием работодателя или менять роль на основе внешнего знания, не предоставленного в snapshot. В этой проверке внешних поисков не было.
