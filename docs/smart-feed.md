# Персональная умная лента

`/smart?workspace=…` открывается кнопкой «Умная лента» из Feed. Лента показывает
непрочитанные статьи по прогнозу личной ценности 1–10, затем по точному времени
поступления и ID. Неоценённые и низко оценённые статьи остаются доступны;
классификация не меняет read/later или явные пользовательские оценки.

Начальный персональный промпт составлен при анализе 139 оценённых материалов,
доступных текстов и авторских пояснений. Он хранится в PostgreSQL под владельцем
аккаунта, а не в общем исходном коде. В UI доступны просмотр и явное редактирование.
`trainingCount` — размер исходной размеченной выборки, не число прогнозов.
Последующие оценки сохраняются существующим механизмом; эта версия не обещает
автоматическое переобучение промпта на каждой новой оценке. Качество прогнозов не
выдаётся за измеренную точность на независимой тестовой выборке.

## Контракты

- `GET /api/ai/smart-feed?workspace_id=…&cursor=…`: авторизация, проверка владельца
  в HTTP и в storage. Профиль и прогнозы другого аккаунта никогда не возвращаются,
  в том числе при одинаковых публичных URL/ID статьи в разных workspace.
- `PUT /api/ai/interests`: меняет только профиль авторизованного аккаунта с CAS
  по точной строковой revision. Пустой/NUL/слишком длинный промпт отклоняется.
  История всех версий сохраняется; предыдущие прогнозы сохраняются отдельно.
- `InterestPrediction` валиден только после проверки целой оценки 1–10, непустой
  причины и закрытого набора confidence. Невалидный ответ не становится прогнозом.
- Курсор содержит версию профиля, оценку и точные строковые arrival/ID.
  Изменение профиля отклоняет старый курсор. Фоновая классификация может изменить
  границы страниц; кнопка «В начало» начинает проход по обновлённому ранжированию.
  Уже открытая страница не обновляется автоматически и не меняет координаты целей.
- В режиме чтения с `from=smart` переход после оценки берёт следующую наиболее
  интересную непрочитанную статью, выход возвращает в умную ленту.

## Выполнение и стоимость

Фоновый worker использует DeepSeek Flash, общий FIFO pool и существующий shared
HTTP transport с HTTPS, DNS/IP validation и учётом времени внешнего запроса.
На входе полный доступный текст, заголовок, исходное описание и приватный профиль.
Отсутствующий fulltext явно обозначается. Заглушки/captcha/video boilerplate
учитываются промптом с низкой уверенностью, без выдумывания деталей.

Контекст и байты проверяются до вызова: слишком большой запрос завершается явной
ошибкой, без скрытого усечения. Запрос и ответ сохраняются для разбора; неизвестная
стоимость удерживает reservation. Классификация учитывается отдельным `ranking`
в том же дневном бюджете, лимит не увеличивается. После отказа бюджета аккаунт
ждёт следующего московского дня. Прерванные запросы автоматически не повторяются.
Пересохранение профиля создаёт новую очередь; получение нового fulltext помечает
старый прогноз устаревшим и пересчитывает его с новым содержимым.

Схема 14 добавляет таблицы профилей, их истории, прогнозов и журнал запросов.
Upgrade выполняется отдельно после резервной копии и репетиции; существующие
статьи, рейтинги, пояснения и receipts не переписываются.
